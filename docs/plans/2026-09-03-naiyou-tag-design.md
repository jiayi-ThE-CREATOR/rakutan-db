# 内容タグ ―― 設計（スペック）

> このファイルは**設計**。実装手順は同日付の `-plan.md` を見ること。
> 実装は `feat/naiyou-tag`（`main` から分岐）で行い、`main` には触らない。
> **同日付の `2026-09-03-haiten-filter-design.md`（配点フィルタ）とは別の PR。**

**ゴール：** 「何の話をする授業か」で科目を探せるようにする。
学部・卒業要件とは**別の層**として置く。

**きっかけ：** wangさんのユーザーインタビュー（2026-09-02）。

> 面白いかどうかは**内容**で判断する。たいていは科目名で分かるが、
> 科目名からは分からないのに中身が面白い授業がある。
> 例：「日本語の歴史」を扱う授業。大学の公式分類に「日本語の歴史」という項目は無い。

公式分類が追いつかない交差を、**タグの組み合わせ**で拾えるようにするのが本質。

## 1. 調べて分かったこと（設計の前提。ここを疑うなら調べ直しから）

### ① ナンバリングから分類を作ると、学部名の言い換えにしかならない ―― 却下した案

最初にナンバリングの学科コード（`08MEEN`→機械、`04MATH`→数学）から
18の分野ラベルを作る案を検討した。**実測して却下した。**

各ラベルについて「最頻の学部がその中で占める割合」:

| ラベル | 件数 | 最頻の学部 | 割合 |
|---|---|---|---|
| 語学/地域 | 2,040 | 外国語学部 | **100%** |
| 語学 | 1,165 | マルチリンガル教育センター | **100%** |
| 人文 | 478 | 文学部 | **100%** |
| 心理・教育 | 330 | 人間科学部 | **100%** |
| 法・政治 | 258 | 法学部 | **100%** |
| 薬学 | 163 | 薬学部 | **100%** |
| 経済 | 107 | 経済学部 | **100%** |
| 環境／情報／建築 | 275 | 工学部・基礎工学部 | **100%** |
| 数学 | 265 | 理学部 | 90% |

ナンバリング由来ラベルの**約 77% が「1学部で 90% 以上」**。
つまり `category`（学部）が既に持っている情報しか運んでいない。
**既存の学部フィルタと重複するだけの層を足すことになるので、この案は捨てる。**

> **判定基準として残す**: 内容タグは、**1つの学部に 90% 以上偏ったら偽タグ**。
> 品質ゲート（4章）で自動チェックする。

### ② 科目名だけでは足りない ―― 手元の実データで確認できる

`data/raw/detail/135063.html`（全学教育「ことばの学問入門」）:

```
開講科目名        【人文】ことばの学問入門
授業サブタイトル   ことばの歴史                    ← 科目名には出てこない
各回題目          動物のコミュニケーション／最初の語族／文字／言語の系統
```

科目名だけを AI に渡すと `ことば・語学` しか付かない。
`歴史` を付けるにはサブタイトルと各回題目が要る。
**インタビューで言われた「科目名からは分からないのに面白い授業」そのもの。**

### ③ シラバス本文はどのコミット済みファイルにも入っていない

`data/raw/` は `.gitignore` 対象（「取得したHTMLのキャッシュ（巨大なのでコミットしない）」）。
このマシンには詳細HTMLが **10件**しか無い。
`web/data/courses.built.json` は 7,906件あるが、本文は焼かれていない。

→ **政岡さんの raw キャッシュをもらう。** 彼は 7,906件をビルドしているので手元にあるはず。
自前で取り直すと `--delay 2.0` で約 4.4 時間、しかも KOAN に無用の負荷をかける。
**`--delay` を短くするのは禁止事項**（README の「踏んではいけない線」）。

### ④ `parse.py` は本文3フィールドを1つも抽出していない

`授業サブタイトル` / `授業の目的と概要` / `第N回 題目` のどれも `courses.json` に入っていない。
抽出そのものを足す必要がある（`labeled()` は2セル行を辞書にしているので、
サブタイトルと概要はキー名を足すだけ。各回題目は `第1回`…`第16回` の連番）。

## 2. 決めたこと

### ① 複数ラベル・単層フラット。検索は AND（交差）

1科目に **1〜3個**のタグを付ける。階層は作らない。

- 「日本語の歴史」を扱う授業 → `ことば・語学` ＋ `歴史`
- 検索で `ことば・語学` と `歴史` を**両方**選ぶと、その科目にたどり着く
- **`歴史×文学` のような合成タグは語彙に作らない。** 交差は検索時に生まれる

**なぜ木ではなくフラットな複数ラベルか（語彙は小さいほうが強い）:**

| | 表現できる組み合わせ |
|---|---|
| 2階層の木（18大類 × 6小類、1科目1葉） | 108 |
| フラット31タグ、1科目1〜3個 | 31 + 465 + 4,495 ≈ **5,000** |

語彙は 31 と小さいのに表現力は 40倍以上。
「キーワードを増やしすぎない」という当初の要求を、木より**よく**満たす。

### ② 語彙は人が固定する。AI は「選ぶ」だけで「作らない」

AI への出力指示は「**下の一覧から1〜3個選べ。当てはまらなければ空を返せ**」。
自由記述を許すと必ず数千語のロングテールが生えて、重なりが消える。

判定できないものは `null`（タグ無し）にする。「その他」は作らない
――『「その他」は画面のラベルであって区分ではない』（`tools/division.py` 冒頭）。

### ③ 語彙（31語・v0）

**正本は `tools/subjects.py` の `VOCAB`。** ここは説明であって定義ではない
（設計時に「33語」と書いていたが、数え間違いで実際は31語だった）。

学問名ではなく**学生の言葉**にする。`score.py` が内部の `attendance` を
画面では「出席の緩さ」と出しているのと同じ原則。

```
ことば・語学   文学        歴史        哲学・思想   宗教
芸術・音楽     文化・地域   社会        政治・法     経済・お金
心理          教育        メディア     ジェンダー   国際
数学          統計・データ  物理        化学        生き物
脳・神経       医療・健康   食         スポーツ・身体
環境・地球     宇宙        情報・プログラミング      AI
機械・電気     ものづくり・建築          エネルギー
```

**「レンズ」タグを意図して残すこと。**
`歴史` `文化・地域` `ジェンダー` `環境・地球` `国際` の5つは、
単独で成立する授業は少なく、ほぼ常に他のタグに乗る
（日本語の**歴史**／**環境**経済学／**ジェンダー**と法）。
**組み合わせ検索が成立するのは、この5つがあるから。**
「歴史学という学部は無い」を理由に落とすと、この設計の中心が消える。

### ④ 学部・ナンバリングは AI への**入力**には使うが、**出力ラベルにはしない**

`08MEEN` は「機械系の科目である」という文脈として AI に渡してよい
（「設計製図」がどの分野の設計かを判断できる）。
しかし `08MEEN → 機械` をそのままラベルにはしない ―― ① の理由。

### ⑤ 語学だけは科目名ルールで先に付ける（AI 呼び出しの節約）

`ドイツ語初級I` `総合英語（Academic Skills）` のように**科目名に言語名を含む
2,479件**（実測）は、`ことば・語学` が確実に付く。
**これは科目名ルールであって、ナンバリング分類ではない。**

注意: **外国語学部の 2,040件のうち 822件は言語名を含まない。**
`【専攻科目】アフリカ地域文化演習a` のような地域研究の科目で、
これらは `ことば・語学` ではなく `文化・地域` `国際` 側に寄る。
**「外国語学部だから語学」と倒さないこと**（①で却下した発想そのもの）。

このルールは AI 対象から科目を外すためのものではない。
語学科目にも `文化・地域` `歴史` が追加で付きうるので、
「`ことば・語学` は確定」として AI に渡し、残り2枠を判断させる。

## 3. データの形

`courses.built.json` の各科目に足す。既存の `division` / `division_source` と同じ形。

```json
"subjects": ["kotoba", "rekishi"],
"subjects_source": "ai"
```

- `subjects` … 語彙のキー配列（0〜3個）。空配列は「判定できなかった」
- `subjects_source` … `"title"`（科目名ルール）/ `"ai"` / `"manual"`（人が直した）
- `_meta.subject_labels` … キー → 画面表示名。`axis_label` と同じ置き方

AI の判定は `data/subjects.ai.tsv` に別途残す（科目ID・科目名・付いたタグ・
根拠にした一文）。**人が上から読んで直せる形にする** ―― このリポジトリは
「数字の根拠を全部提示できる状態を保つ」（`score.py` 冒頭）が前提。
`data/subjects.manual.tsv` に人が書いた行があれば、そちらが AI に勝つ。

## 4. 語彙を確定する前に必ず通す品質ゲート

**AI を流した直後、UI に繋ぐ前**に3つの表を出す。数分で終わる。

| ゲート | 見るもの | 不合格のときにやること |
|---|---|---|
| **頻度** | 各タグの件数 | 50件未満＝死にタグ（消すか統合）。3,000件超＝広すぎ（分ける） |
| **共起** | タグ2つの同時出現件数の行列 | `歴史 ∩ ことば・語学` が数件しか無い＝AI が付け惜しんでいる。プロンプトを直す |
| **学部集中度** | タグごとに最頻 `category` の割合 | **90% 以上なら偽タグ**（①の再発）。定義を書き直す |

この3表を PR の説明に貼る。合格するまで UI には繋がない。

## 5. 画面 ―― 中央のモーダルで「掘っていく」

右のレールにはボタンと選択済みチップだけを置き、本体は中央に出す。

```
右レール
┌────────────────────────┐
│ 授業内容                │
│ ┌────────────────────┐ │
│ │ 何の話？        ▸  │ │
│ └────────────────────┘ │
│  (歴史 ✕)(ことば・語学 ✕)│  ← 閉じても何を選んだか分かる
└────────────────────────┘
```

```
モーダル（中央）
（`###` は AI を流すまで確定しない ―― `ことば・語学` 2479 だけが実測値）

┌──────────────────────────────────────────┐
│  何の話がききたい？                  ✕   │
│  ┌────────────────────────────────────┐  │
│  │ 🔍                                 │  │
│  └────────────────────────────────────┘  │
│  ことば・語学 2479   歴史 ###            │
│  文化・地域 ###      脳・神経 ###          │
│  食 ###  宇宙 ###  ジェンダー ###  …     │
│                                          │
│  ── 「歴史」を選んだあと ───────────    │
│  ▸ 歴史 ### ✕                            │
│    さらにしぼる                           │
│    ことば・語学 ##   文化・地域 ##        │
│    芸術・音楽 ##     政治・法 ##          │
│    （0件になるタグは出さない）            │
│                        [ 決定 ##件 ]     │
└──────────────────────────────────────────┘
```

- **複数選択は AND**。選ぶほど件数が減る
- **選択済みタグとの共起件数を各タグに出す。0件のタグは表示しない。**
  「語学 ∩ 歴史」のような交差を**人が掘り当てられる**ようにするのがこの画面の目的
- 件数は既存のチップと同じ数え方をする ―― **曜限フィルタの「前」で数える**
  （そうしないとコマを押した瞬間に他が全部0件になり、次の一手が打てない。`app.js` に同じ注意書きあり）
- 検索ボックスはタグ名の部分一致。31語でも打って飛べたほうが速い
- URL は `?subject=rekishi,kotoba`

## 6. やらないこと

| やらないこと | 理由 |
|---|---|
| ナンバリング／学部からタグを機械生成する | ①の実測どおり、学部名の言い換えにしかならない |
| タグに階層を作る | 交差は検索時に生む。木は「日本語の歴史」を予測できない |
| `歴史×文学` のような合成タグを語彙に入れる | 語彙が組み合わせ爆発する。組み合わせは検索側の仕事 |
| 判定できない科目に「その他」を付ける | 「その他」は画面のラベルであって区分ではない（`division.py`） |
| 科目名だけで AI を流す | ②の実証どおり、狙っているケースが取れない |
| `scrape/fetch.py --delay` を縮めて自前で取り直す | 禁止事項。まず政岡さんの raw をもらう |
| 内容タグを楽単スコアに入れる | スコアはシラバスの事実項目だけ（`score.py` 方針2）。内容は好みであって負荷ではない |
| このPRで配点スライダーに触る | 別PR |

## 6.5 実装して分かったこと（2026-09-04）

- **設計の中心にあるケースは通った。** `ことばの学問入門`（科目名に「歴史」は
  出てこない）に、本文を渡すと `ことば・語学 ＋ 歴史` が付いた。
  科目名だけでは `ことば・語学` しか付かない ―― 本文を集める理由が実証できた
- **本文が「英文シラバスをご参照ください。」の1文しか無い科目がある。**
  最初のプロンプトでは `Cross Cultural Psychology` に何も付かなかった。
  科目名からは明らかなので「概要が空なら科目名から確実に言えるものだけ付ける
  （想像で補わない）」を足した。学生も「たいていは科目名で分かる」と言っている
- **モデルはやや多めに付ける傾向がある**（`ことばの学問入門` に `生き物` が
  付いた ―― 第1章が動物のコミュニケーションなので誤りではない）。
  多すぎるかどうかは10件では決められないので、頻度表で全量を見てから調整する
- **macOS の python.org 版 Python は TLS の証明書を検証できない。**
  `tools/subject_tag.py` は既定 → certifi の順に試し、どちらも駄目なら
  直し方を出して止まる（検証を切る選択肢は置いていない）

**流したら `scrape/years.py` も必ず流す**（`eligible_years` が消える）。
