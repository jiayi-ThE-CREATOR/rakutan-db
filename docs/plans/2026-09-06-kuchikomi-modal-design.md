# 口コミを中央モーダルへ出す（科目詳細の作り直し・案A-1）

2026-09-06 ｜ 設計 ｜ wang の依頼（詳細に情報が多すぎる・字が小さい・口コミは今後さらに増える）

## 1. 何が問題か

**実測**（口コミ4件の科目 135327・iPhone 390px・`main` = 04ef707）：

| | 高さ |
|---|---|
| カード（詳細を開いた状態） | 940px |
| うち詳細（`.detail`） | 695px |

詳細のうち口コミ節が **約 360px**。中身は同じ口コミが3つの形に分かれている：

1. 一言3件（`.rvn`・13px）
2. 集計チップ（`.rvf`・**11.5px**）
3. 「N件すべてを1件ずつ読む →」（`.panelBtn`）

字が小さいのは `--fs-xs = 11.5px`（`tokens.css:115`）を集計チップ・`.bandNote` に使っているため。
**そして口コミが増えるほど詳細が伸びる。** 一言は3件で頭打ちだが、これは
「増えた分は読ませない」で高さを止めているだけで、増えた口コミの置き場所は無い。

### いま本番で壊れているもの（この作業で直る）

本番は Cloudflare の静的配信なので `CAN_POST = false`（`app.js:1590`）。
`#fab` は `applyPostMode()` が隠すが、**詳細の `.reviewBtn`「この科目の口コミを書く」は隠れない。**
押すと投稿フォームが開き、最後まで入力できるが `$("#send").onclick` の
1行目が `if (!CAN_POST) return;` なので**送信しても何も起きない**。

実測（静的モード＝本番と同じ）:

```
CAN_POST: false   mode: static
fab display: none                    ← FAB は正しく隠れている
reviewBtn exists: true visible: true ← こちらは隠れない
sheet open: true                     ← 出せないフォームが開く
```

本番で実際に投稿できる道は、ヘッダの `/kuchikomi`（独立ページ → Worker
`/api/kuchikomi` → GAS）**だけ**。

## 2. 決めたこと

**口コミは詳細から出し、中央モーダル1つに集約する。入口はカードに置く。**

カードの下端に操作バーを1本足し、そこに「読む・書く・時間割」を並べる。
詳細からは口コミ節と操作ボタンを**全部外す**。

```
┌─────────────────────────────────────┐
│ 【総合】カーボンニュートラル…    86.9 ☆│  .head（role="button"・従来どおり）
│ 金1・鈴木 智博・豊中・全学教育科目      │
│ 軽め  出席の緩さ・小テストの少なさが…    │
│ 1限（体感コスト大）                    │
├─────────────────────────────────────┤
│ 💬 口コミ 4件を読む ›  │ ✎ │ ＋ 時間割 │  .cardActs（新設・.head の外）
└─────────────────────────────────────┘
      ↓ 詳細を開くと
┌─────────────────────────────────────┐
│ 成績評価の内訳（KOANの%の積み上げバー）  │
│ この科目のKOAN公式シラバスを見る ↗      │
└─────────────────────────────────────┘
```

**効果（同じ科目・同じ端末で実測）**

| | いま | この設計 |
|---|---|---|
| 詳細（`.detail`） | 695px | **170px** |
| カード（詳細を開いた状態） | 940px | **約 470px** |

カードは閉じた状態で高くなる。操作バーの実測は **1行 58px / 2行 79px**（390px 幅）。
「読む」は2行（下記）なので **79px**。ここから `.head` の中の `.rvb` バッジを
外すぶんが差し引かれる ―― **正味の増分は実装時に実測して HANDOFF に残すこと**。

1画面あたり見えるカードが半枚ぶん減る。これは「時間割に追加が詳細を開かないと
押せない」「口コミを読むのに2回押す」を解くための対価として受け入れる。

### なぜ詳細に口コミ入口を残さないか

操作バーはカードに常に出ている。詳細を開くとバーは詳細のすぐ上に居るので、
詳細の中にもう1つ同じボタンを置くと、**画面上に同じ操作が3cm 差で2つ並ぶ**。

同じ判断を過去にしている：カード右上の ☆ があるので詳細から ☆ を外した
（`app.js` の `detailHtml` 前のコメント）。同じ理由で、時間割・口コミも
カード側に一本化する。

### 却下した案

- **カードごとモーダルにする（詳細もモーダルの中）** ―― PC の右カラム
  `#inspector` の存在意義が無くなる。#122 で「選んでいないときは右カラムを
  畳んで中央寄せ」を入れたばかりで、今回の範囲を超える。
- **バッジの位置のままボタンにし、時間割は ☆ の下に丸い ＋** ―― カードは
  高くならないが、右上が ☆ ＋ 丸ボタン2つで詰まる。文字の無い `＋` は
  「時間割に追加」だと押すまで分からない。

## 3. モーダルの中身

`#panel` を**上下中央のモーダル**（最大幅 560px）にする（いまはスマホ＝下から全画面シート、
PC＝右カラムの集計と差し替え、の2形態）。**PC・スマホで同じ形にする。**

```
┌───────────────────────────────┐
│ 【総合】カーボンニュートラル…      ✕ │ ← 固定（スクロールしない）
│ 口コミ 4件 ― 実際に取った人が書いたもの │
├───────────────────────────────┤
│ みんなの平均                        │
│ ┌──────────┐┌──────────┐        │
│ │ 出席   2.0/2 ││ 授業中 0.0/2 │        │ ← 数値 15px（いまは 11.5px）
│ └──────────┘└──────────┘        │
│ 数字は4件の平均。出席は 0 なし〜2 毎回…  │
│ ── 1件ずつ ─────────────────      │
│ 2026年受講                          │
│ 鬼楽単。出席するだけでいい             │ ← 本文 15px / 行高 1.8
│ [出席 毎回][授業中の課題 ―][授業外 ―]  │ ← 属性は本文の下に畳む
├───────────────────────────────┤
│ ［ この科目の口コミを書く ］           │ ← 固定
└───────────────────────────────┘
```

字の大きさ（いま → この設計）:

| | いま | この設計 |
|---|---|---|
| 口コミ本文 | 13px / 行高 1.6 | **15px（`--fs-base`）/ 行高 1.8** |
| 集計の数値 | 11.5px | **15px（`--fs-base`）** |
| 受講年・属性 | 11.5px | 13px（`--fs-sm`） |

トークンに 14px も 12px も無い。**この表のために新しいトークンを足さない**
―― `--fs-*` を増やすと「どれを使うか」の判断が毎回必要になる。

**一言3件（`.rvn`）は無くす。** モーダルには全件が1件ずつ出るので、
先頭3件を別の形でもう一度出す意味がない。ただし**口コミの原文が
モーダルの外から完全に消えるのは避ける** ―― 一覧の「読む」ボタンの2行目に
先頭1件を出す（4章）。押す理由がそこに要る。

**属性を本文の下へ移す。** いまは `出席 毎回 ／ 授業中の課題 ― ／ 授業外の課題 ―`
が本文より先に来るので、読みたい一言に届く前に「―」の並びを読まされる。

## 4. 変更するもの

### `web/assets/app.js`

| 場所 | すること |
|---|---|
| `card()` | `.head` の**外**（`.favBtn` と同じ階層）に `.cardActs` を足す。中身は下記 |
| `card()` | `.head` の中の `.rvb` バッジを外す（件数は `.cardActs` のボタンが持つ） |
| `detailHtml()` | 口コミの `.dSec` を丸ごと削除。`.dActs` から `.ttAddBtn` と `.reviewBtn` を削除（`.koanLink` だけ残す） |
| `reviewHtml()` | 詳細用（一言＋チップ）をやめ、**モーダルの「みんなの平均」専用**にする。呼び出し元は `openPanel` 1箇所だけになる |
| `panelEntry()` | 本文（`.pNote`）を先に、属性（`.pLine`）をチップにして後ろに |
| `openPanel()` | `isDesktop()` の分岐を削除。PC でも同じモーダルを開く |
| `panelSetOpen()` | PC のインライン差し替えの後始末（`.pList` の除去・`.rv[hidden]` の復帰・`.panelBtn` の文言戻し）を削除 |
| `panelBtnFor()` | 削除（`.panelBtn` が無くなる） |

| `.ttAddBtn` のハンドラ | 押した後の文言 `"時間割に入っています"` → `"✓ 時間割に入れた"`（バーに収まる長さ） |

`.cardActs` の中身（`n` = 口コミ件数）:

```
n > 0:  [💬 口コミ n件を読む ›]  [✎]  [＋ 時間割]
n = 0:  [✎ 最初の口コミを書く ›]       [＋ 時間割]
```

- 「読む」= `<button class="rvBtn" data-id aria-haspopup="dialog">`。**2行**にする：

  ```
  💬 口コミ 4件を読む ›
  「鬼楽単。出席するだけでいい」ほか      ← 12px・grey・1行で省略（…）
  ```

  プレビューの出どころは `c.reviews.notes[0]`。`notes` は `publish:false` を
  除いたぶんしか入っていないので、**`n > 0` でも `notes` が空の科目がある**
  （`reviewHtml` の上のコメント参照）。その場合は2行目を出さず1行のままにする
  ―― 空の2行目で高さだけ増やさない
- 「書く」= `<a class="wrBtn" href="/kuchikomi?c=<id>" aria-label="この科目の口コミを書く">✎</a>`
  ―― ボタンでなく **`<a>`**。別タブで開けるようにするため
- 「時間割」= 既存の `<button class="ttAddBtn" data-id aria-pressed>` をそのまま移す
  ―― ハンドラは `#list` への委譲で既に動くので、置き場所が変わるだけ

7,906件の大半は口コミ0件なので、`n = 0` の形が一覧の既定の見た目になる。
ここが投稿への一番自然な入口になる（口コミを増やすのが今回の目的の半分）。

### `web/assets/app.css`

- `.cardActs` / `.rvBtn` / `.wrBtn` を新設（`.card` の下端・`.head` の外）
- `#panel` を `.sheet` の使い回しから外し、専用の中央モーダルにする
  ―― `.sheet` は投稿フォーム（`#sheet`）が下からのシートのまま使い続けるので、
  クラスを分けないと両方が動く
- `.rvn`（一言3件）と `.panelBtn` の規則を削除
- `.rvf` を「みんなの平均」の2列グリッドに作り直し、`.pEntry` 系の字を上げる
- **クラス名の衝突に注意**：`.nav` と `pnArrow` の事故（`app.js:1331` のコメント）と
  同じ型を作らないこと。`.rvBtn` / `.wrBtn` / `.cardActs` は現在の CSS に無いことを確認ずみ

### `web/assets/kuchikomi.js`（`?c=<id>` で科目を選んだ状態で開く）

いまこのページは URL パラメータを一切見ない（`URLSearchParams` の使用なし）。
`init()` の末尾に足す：

1. `?c=<id>` を読む。無ければ何もしない（従来どおり）
2. `ROWS`（`/data/timetable.json`・7,906件）から `id` で引く。見つからなければ何もしない
3. `state.faculty` と `state.semester` が両方入っているとき（＝`osaka_u_settings`
   から復元できたとき）だけ、その場でモーダルを開く
   - `row.slots` が空 → `openEditor({ kind:'extra', id })`
   - そうでなければ `slots[0]` を曜日・時限に分解 → `openEditor({ kind:'slot', day, period })`
     を呼び、`renderModalSubjectOptions()` の後で `els.modalSubjectSelect.value = id`
4. 候補一覧にその `id` が無かった場合（学部が合わない等）はモーダルを閉じ、5 に落とす
5. 学期・学部が未設定のときは**モーダルを開かず**、選択欄の上に
   「<科目名> の口コミを書きます。まず学期と学部を選んでください」の1行を出す。
   両方選ばれた時点で 3 を実行する

`getSubjects()` も `extraCandidates()` も `state.faculty && state.semester` が
無いと空を返す（`kuchikomi.js:381` / `:407`）ので、この順序でないと
「開いたのに候補が0件」になる。

### `web/index.html` / `templates/shell.html`

`#panel` のマークアップに固定フッタ（`この科目の口コミを書く` → `/kuchikomi?c=<id>`）を足す。
`#fab` と `#sheet`（ページ内投稿フォーム）は **API モード（`server.py`）用に残す**。
本番では従来どおり `applyPostMode()` が隠す。

## 5. URL と履歴の契約（変えない）

`?c=<id>` はいまのまま：

- 開くとき `history.pushState({panelCourse:id})`
- 閉じる手段（✕・幕クリック・Esc・Android の戻る）は全部 `history.back()` を通り、
  実際に閉じるのは `popstate` の1箇所だけ
- 共有リンクで直接入ってきた場合は `openPanel(initId, false)`

**PC でも履歴に積む**（2026-08-24 の決定）は維持する。変わるのは
「PC のときインラインに差し込む」分岐が消えることだけ。

共有リンク（PC・`?c=<id>`）で `showDetail` も呼ぶ挙動は**残す**。一度
「モーダルは完結した部品だから要らない」と判断して外したが、2026-09-08 に
main を取り込んだところ `tools/test_eval_raw.mjs`（#129）が
「`?c=` で開いた先に詳細が在る」ことを前提にしていて落ちた。
外していると、共有リンクで来た人はモーダルを閉じた瞬間に既定の一覧へ
放り出される ―― 送られた科目の痕跡が画面から消える。戻すほうが正しい。
スマホは詳細がカードの中に開くので、ここでは呼ばない。

Esc の順番も維持：モーダルが開いていればモーダルを閉じる、開いていなければ
PC の右カラムの詳細を閉じる（`app.js:1214-1219`・#122 で入ったばかり）。
