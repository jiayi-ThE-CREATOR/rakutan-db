# 時間割を端末どうしでそろえる（設計）＋ 教科書マーケットとマイページの統合

2026-10-29 wang 決定。きっかけは教科書マーケット（阪大教科書センターとの協業）。
マーケットの「受け取り・持ち込みの日時」は、本人の時間割と照らして選べる枠だけを出す。
その時間割は**ラクハンの「私の時間割」をそのまま使う**（2つ目の時間割は作らない）。
クーポン・時間割・カレンダー連携も、いずれラクハンのマイページにまとめる。

その前提として、次の3つを片付ける。

| | やること | 状態 |
|---|---|---|
| ① | 時間割を端末どうしでそろえる（スマホで作って PC で予約しても同じ時間割） | **この PR** |
| ② | メールでログインした人も、マイページの門（data-gate）を通れる | **済み**（maillogin.js が friend:true で発行。`test_maillogin.mjs`・`test_gate.mjs` が見張っている） |
| ③ | カレンダー連携（空き時間を読む）を入れるときの方針の変更とプライバシーの文 | **マーケットと一緒に入れる**（§6 に文案だけ置く） |

## 1. 決まったこと

- 同じアカウントで、この端末の時間割と保存されている時間割が違うときは、**毎回本人に聞く**（「新しい方」「和集合」は採らない）
- この端末が空なら聞かない（新しい端末）。保存されている方を黙って使う
- 聞いている間は送らない。✕ で閉じたら次に開いたときにもう一度聞く
- カレンダー連携はマーケットと一緒に作る。それまで about の文は変えない（無い機能を書かない）

## 2. なぜ新しい表が要るか

`timetables`（2026-10-05）は**数える用**で、学期ごとの科目 ID しか持たない。
ブラウザの時間割（`rk_timetable`）は「どのコマに何を置いたか」を持ち、
曜限の無い科目を自分で選んだコマに置いた場合など、ID だけからは元に戻せない。
だから `rk_timetable` を**そのまま1行**持つ表を足す。

```sql
CREATE TABLE IF NOT EXISTS timetable_docs (
  line_user_id TEXT PRIMARY KEY,   -- アカウント ID（timetables と同じ）
  doc TEXT NOT NULL,               -- cleanDoc を通した rk_timetable
  updated_at INTEGER NOT NULL
);
```

- 書くのは `PUT /api/profile`（今までの本文に `doc` を足す）。今までの batch とは**別に**書く ――
  表をまだ作っていない D1 でも、数える用の保存は落とさない
- `doc` の無い PUT（古い画面）は触らない
- `cleanDoc`：コマは「月〜金 × 1〜6」、科目 ID は `cleanIds` と同じ形だけ通す
- アカウントをつなぐとき（LINE＋メール）は、時間割と同じく**新しい方**を主アカウントへ（account.js。これも別の batch）

## 3. API

- `GET /api/profile` → `{ ok, doc, at }`。写しが無ければ `doc: null`。未ログインは 401、読めなければ 500
- `PUT /api/profile` → 今まで通り。`doc` があれば `timetable_docs` も上書き

## 4. 画面の流れ（usersync.js）

ログインが分かったら（gate.js の `/api/me`）、**送る前に** GET で保存を聞く。

| 保存 | この端末 | どうするか |
|---|---|---|
| 無い・聞けない | ― | 今まで通り（空でなければ送る） |
| ある | 空 | 保存されている方を書き戻して読み直す（聞かない） |
| ある | 同じ | 今まで通り |
| ある | 違う | ダイアログで聞く。答えるまで送らない |

- 「同じ」はサーバーが通す形（cleanDoc と同じ条件）だけで比べる。通らない値が端末に残っていても毎回聞かないため
- 「保存されている方」を選んだら書き戻してページを読み直す（画面はもう古い時間割で描いてある）。
  ただし localStorage に書けていない端末では読み直さない（空に戻って同じことを繰り返すため。`rkStore.timetableSaved()`）
- ダイアログは `gate.css` の `.gateDlg` を使う（新しい CSS は無い）

## 5. 分かっている穴

- 全部外した時間割も「保存がある（0科目）」として残るので、古い端末を開くと「違う」と聞かれる（それで正しい）。
  ただし `doc` を送らない古い画面のまま全部外すと、写しは前のまま残る
- 同じ端末で2つのタブを開いたまま、片方で変えても、もう片方は読み直すまで古い
- 学年・学部はそろえていない（今まで通り端末ごと。サーバーには数える用に送っている）

## 6. ③ カレンダー連携を入れるときに変えるもの（文案・まだ入れない）

マーケットの「日時」を、本人のカレンダーの空きとも照らすために、GUILD の日程調整と同じ連携
（Google は `calendar.freebusy`・`calendar.calendarlist.readonly` のみ／iPhone は iCloud の公開カレンダーのリンク）を入れる。
そのとき同じ PR で直す：

- **about の「保存するもの」**（`web/about.html` の LINE・メールの行の下）に足す:
  > **カレンダーをつないだ人**：Google カレンダーや iPhone のカレンダーから、**空いているかどうかだけ**を読みます。
  > 予定の件名・場所・参加者は読みません。つなぐための情報（Google の許可・カレンダーのリンク）は、外すまで保存し、外すと消します。
- **マーケットのお知らせをメールで送る**（2026-10-29 wang 決定）なら、「メールアドレスそのものは保存しません」と食い違う。
  お知らせを受け取ると選んだ人だけアドレスを保存する形にし、about の文も同時に直す
- `web/mypage.html` の削除ダイアログの注記「OAuth連携を持たないログイン不要設計」は、カレンダーへの**書き出し**の話としては正しいままだが、
  サイト全体の説明としては古くなるので「書き出しは OAuth を使わない」と言い直す
- OAuth の同意画面は「本番環境」にする（テストのままだと 7 日で連携が切れる。GUILD で実測）
