# 負担ランクと新しい口コミ（設計）

2026-10-13 wang 決定。きっかけは しゅんや の指摘③④（Discord #ラクハンーui＆design 10/6）。
チーム向けの説明スライド：https://claude.ai/artifact/AsGcKQziS7V89FJjZXw2My

## 1. 何を変えるか（決まったこと）

| | 今 | これから |
|---|---|---|
| 大きく出すもの | 相性度（0〜100 の数字）＋ band（軽め〜重め） | **負担ランク SS・S・A・B・C**（SS がいちばん楽） |
| 相性度 | 常に数字で出す | **％**。配分を動かした人にだけ出す |
| 負担の元 | シラバス 8 割＋口コミ最大 2 割 | 新しい口コミがあれば**口コミだけ**。無ければ下の表 |
| 口コミの質問 | 出席3択・課題の重さ・難易度1〜10 など | 項目ごとに **1〜5**（シラバスにある項目だけ出す） |

負担の元は科目によって3通り：

| 科目の口コミ | 負担の計算 | ランクの区切り |
|---|---|---|
| 新しい口コミが1件以上 | 新しい口コミだけ（§3） | 固定（§4） |
| 古い口コミだけ | **シラバス式 60%＋古い口コミ 40%**（人数によらず固定） | 分布を5等分（§4） |
| 口コミ無し | シラバス式だけ（今と同じ） | 分布を5等分（§4） |

## 2. 言葉

- **負担**：科目そのものの重さ。誰が見ても同じ。ランクで出す。
- **相性度**：その人の配分（重み）で計算した合い方。人によって違う。％で出す。
- **配分**：5項目の重み。既定は テスト50・発表20・レポート15・出席15・小テスト10。
  今の「好みの重さ」の目盛り（`rk_konomi`）と同じもの。
- **5項目**：`exam`（テスト）／`report`（レポート・課題／宿題）／`attendance`（出席）／`quiz`（小テスト）／`presentation`（発表）。
  シラバスの内訳のバケツ・目盛りと同じキー。

## 3. 新しい口コミ（form v5）

### 質問の画面（`web/kuchikomi.html` / `kuchikomi.js`）

- 科目の成績の内訳（`eval_ratio`）にある項目だけを出す。1行＝`[実際はなかった] [1]〜[5]`、1タップで答える。
- 行の見出しに「（シラバス：成績の70%）」を添える。
- 折りたたみ「シラバスに無いけど、実際にはあったもの」から、残りの項目を行として足せる。
- 内訳が取れない科目（`eval_ratio` が無い）は5項目すべて出す。
- 1〜5 の目安を行ごとに出す（スライド10ページの文言）。
- 残す：受講年度・テストの持ち込み（テストの行があるときだけ）・教科書の質問・一言。
- 消す：出席3択・授業中／授業外の課題・テストの有無と難易度1〜10・レポートの有無と字数。

### 送る値

1件の `review` に `form_v: 5` と `items` を足す。`items` は**5項目すべて**に 0〜5 を入れる：
1〜5＝答えた値、0＝「実際はなかった」または「出さなかった・足さなかった項目」。
未回答のまま送らせない（シラバスにある行は必須）。

```json
{"form_v": 5, "items": {"exam": 2, "report": 0, "attendance": 0, "quiz": 1, "presentation": 0}, ...}
```

### スプレッドシートの列（しゅんや に依頼）

GAS に次の6列を足してもらう。**GAS が直るまで v5 のフォームは本番に出さない**
（Worker は body をそのまま GAS に渡すので、知らない鍵は黙って落ちる）。

| 列名 | 値 |
|---|---|
| フォーム版 | 5 |
| テスト(0-5) | 0〜5 |
| レポート・課題／宿題(0-5) | 0〜5 |
| 出席(0-5) | 0〜5 |
| 小テスト(0-5) | 0〜5 |
| 発表(0-5) | 0〜5 |

古い列（出欠・授業中の課題 など）は残してよい。v5 の行では空になる。

### 取り込み（`tools/ingest_reviews.py`）

「フォーム版」列が 5 の行は v5 として読み、`data/reviews.json` に
`{"v": 5, "course_id", "items": {...}, "taken_year", "exam_bring", "note", "at", ...}` で入れる。
古い行の読み方は変えない。

## 4. 計算

### 新しい口コミがある科目（`reviews.py` / `score.py`）

1. 1人の負担 ＝ Σ(配分 × items) ÷ Σ配分（0〜5、大きいほど重い）。既定の配分で計算する。
2. 科目の負担 ＝ 1人の負担の平均（v5 の行だけ。別クラスとの共有 `reviews.share` は v5 にも効かせる）。
3. 同じ回答の重複は今と同じく1人に数える（`_IDENTITY` に `items` を足す）。
4. ランクは**固定の区切り**：負担 <1 → SS／<2 → S／<3 → A／<4 → B／それ以外 → C。
5. 項目ごとの平均（0〜5）も built に載せる。ブラウザが相性度を計算するのに使う。
6. 「実際はなかった」が過半数の項目は `syllabus_mismatch` に名前を残す（画面で「シラバスと実際が違うようです」）。

### 新しい口コミが無い科目

- 今の `aishoudo` をそのまま使う。ただし古い口コミがある科目は体感層の取り分を**人数によらず 0.40**
  （今は 1人 6.7%〜3人以上 20%）。
- ランクは**分布の5等分**：全科目（判定できたもの）の `overall` を5等分した境目を build で求め、
  `_meta.rank_cut` に保存する。点が高いほど楽なので、上位 20% が SS。
  口コミが十分たまったら、口コミを答え合わせに使ってシラバス式を直す（別の作業）。
- 「情報不足」「判定不可」「参考値」はランクを出さず、今の表示のまま。

## 5. 相性度（％・ブラウザだけ）

- 配分（`rk_konomi`）が既定のままなら、％は出さない。代わりに「配分を動かすとあなたとの相性度が出ます」。
- 新しい口コミがある科目：％ ＝ 100 − (Σ自分の配分 × 項目の平均 ÷ Σ自分の配分) × 20。
- それ以外の科目：今の `fitOf`（目盛り＝負担の倍率）の結果をそのまま％として出す。
- `score.py` は好みを持たない（今と同じ。好みはブラウザの中だけ）。

## 6. 表示（`app.js` ほか）

- カード：左に負担ランクの大きな文字、右に（配分を動かした人だけ）相性度％。
- その下に根拠：シラバス由来（「試験 70%」「毎回小テスト」）と口コミ由来（「口コミ7人」「シラバスと実際が違うようです」）。
  どちらから出したランクかを必ず書く（「口コミ○人から」／「シラバスから推定」）。
- band の文字（軽め〜重め）は出さない。絞り込み・並び順は負担で行う。
- `pages.py`（静的ページ）・`about.html`・LINE の文言も同じ言い方にそろえる。
- `CLAUDE.md`「単一の総合スコア（S〜F や100点満点）を見出しにする」の行を書き換える。
  根拠を必ず添えること、相性度は人ごとであることを理由として残す。

## 8. 検査

- `tools/test_reviews.py`：v5 の集計（無し＝0、重複、共有、mismatch）
- `tools/test_ingest_reviews.py`：v5 の列の読み取り
- `tools/test_aishoudo.py` ほか：古い口コミ 0.40、ランクの区切り（固定・5等分）
- `tools/test_conditions.py` などの件数固定は、動いたら理由を書いて直す
- ブラウザ：％が既定の配分では出ないこと、動かすと出ること

## 9. 分かっている副作用

- 古い口コミの取り分 20%→40% で、口コミがある科目の点数が動く（実測は ② の PR に書く）。
- 口コミ1人だけの科目（今 219）は、その1人で負担が決まる（wang 了承ずみ）。
- ランクの意味は元によって少し違う（固定の区切り／5等分）。だから根拠に元を書く。
