# メールでログイン（設計）

2026-10-19 wang 決定。きっかけは しゅんや の指摘①（Discord #ラクハンーui＆design 10/6）：
パソコンで見る人が多いのに、LINE ログインは「スマホの LINE で QR を読む」が要って面倒。

## 1. 決まったこと

- ログインは **LINE（おすすめ）か メール** の二択にする。LINE をやめはしない
- LINE の入口には、パソコンだけに「QR コードをスマホの LINE で読み取る」の一言を出す（PR で先に出す・§6）
- メールは**阪大のアドレスに限らない**
- LINE とメールのアカウントは**合わせない**（同じ人でも別アカウント。時間割・お気に入りも別）
- **メールアドレスそのものは保存しない**（§3）
- 今「LINE の友だち」に限っている機能は、**メールでログインした人にも開く**
- おすすめ理由は短く2つ：「新しい機能のお知らせが LINE に届く」「LINE のトークから科目をすぐ探せる」

## 2. 送る仕組み

- **Resend**（メール送信サービス）を Worker から API で呼ぶ。鍵は secret `RESEND_API_KEY`
- Cloudflare の Email Service は使えない。送るドメインの DNS が Cloudflare に無いと使えず
  （公式：「You must be using Cloudflare DNS」）、`nocode-sol.co.jp` の DNS は Xserver（xbiz.ne.jp）にある。
  会社のメール（Google Workspace）も載っているドメインなので、DNS を Cloudflare へ移す案は採らない
- 送信元は**子ドメイン** `login@mail.nocode-sol.co.jp`。DNS のレコード（SPF・DKIM・バウンス用 MX）は
  `mail.nocode-sol.co.jp` の下にだけ足す ―― 会社の本体のドメインの設定（SPF・MX）には触らない。
  レコードの値は Resend にドメインを足したときに出るので、それを吉村さんに Xserver へ入れてもらう
- 無料枠は **1日100通・月3,000通**。超えたら画面に「今日はメールログインが混み合っています。LINE でログインしてください」

## 3. 流れ

1. ログインの説明（`#gateDlg`・マイページ）に「LINE でログイン（おすすめ）」と「メールでログイン」を並べる
2. メールを選ぶと入力欄。送信で `POST /mail/start {email, next}`
3. Worker：形式を確かめ、**送信回数の制限**（同じアドレス 1時間3通・同じ IP 1時間10通）を通ったら、
   使い捨ての文字列入りのリンクを Resend で送る。画面には「メールを送りました」だけ出す
   （アドレスが正しいかどうかを外から確かめられないように、成否で文言を変えない）
4. リンク `GET /mail/login?t=…` → 文字列を確かめて、セッション Cookie（今の `rk_sess` と同じ形）を置き、`next` へ戻す

### 別の端末で押しても、送った端末がログインする（2026-10-20 追加・wang 依頼）

- 送るとき「待ち番号」（rid）を作り、送った端末の HttpOnly Cookie `rk_mailwait` とリンクの中に入れる。D1 の `mail_wait` に行を作る
- リンクが押されたら（どの端末でも）その行に `m:<識別子>` を書く。押した端末にもセッションを出す
- 送った端末は `GET /mail/poll` を3秒ごとに聞き、書かれていたらセッションを受け取る（1回だけ・`taken`）。
  期限だけ localStorage（`rk_mailwait_until`）に置き、ページを開き直しても待ちを続ける
- **確認の番号は付けない**（wang 判断）。他人が自分の端末からあなたのアドレスで送り、あなたがそのリンクを押すと、
  他人の端末があなたとして入れる。守る中身が時間割・お気に入りだけなので受け入れた

### 使い捨ての文字列

- 中身：`{h, exp, n}` を HMAC-SHA256 で署名（今のセッション Cookie と同じ作り）。
  `h` はアドレスの識別子、`exp` は 15分後、`n` はランダムな値
- **1回だけ**：使った `n` を D1 に記録し、2回目は通さない（期限が過ぎた行は消す）

### アドレスを保存しない

- 識別子 `h` ＝ HMAC-SHA256（secret, 小文字にして前後の空白を落としたアドレス）。secret が無いと元に戻せない
- アカウントの ID は `m:` ＋ `h`。今 `line_user_id` の列に入っている所（お気に入り・時間割・プロフィール）に、そのまま入れる
- Worker はアドレスを送信の間だけ使い、どこにも書かない（ログにも出さない）
- ⚠️ **Resend 側には送信の記録（宛先を含む）が残る**（サービスの仕様）。about の「集める情報」にその旨を書く

### セッション

- 期限は LINE と同じ 30日
- メールの人は「LINE の友だち」の確認が無い。門（gate.js・`/api/me`）は「ログイン済み」なら開く扱いにする
- LINE の bot（トークで科目を探す）はメールの人には使えない（LINE のアカウントが無いので）

ログインの説明：

> ログインすると、口コミを読む・配分を動かす などが使えます
>
> ［LINE でログイン（おすすめ）］
> ・新しい機能のお知らせが LINE に届く
> ・LINE のトークから科目をすぐ探せる
>
> ［メールでログイン］

送るメール：

> 差出人：ラクハン &lt;login@mail.nocode-sol.co.jp&gt;
>
> ラクハンにログインするためのリンクです。下のリンクを押すと、ログインが完了します。

> スマホで押しても大丈夫です。メールを送ったパソコンも、自動でログインします。
>
> このメールに心当たりがない場合は、何もしなくて大丈夫です（誰かがアドレスを打ち間違えた可能性があります）。リンクを押さなければ、何も起きません。
>
> ラクハン（学生団体 GUILD・非公式）
> このメールは送信専用です。返信はできません。

## 5. 前提（まだ済んでいないもの）

1. wang が Resend のアカウントを作り、`mail.nocode-sol.co.jp` を足す（地域は東京があれば東京）
2. Resend が出した DNS レコードを、吉村さんが Xserver に入れる → Resend で「確認済み」になる
3. `RESEND_API_KEY` と、識別子用の secret を Worker に入れる（`wrangler secret put`）

## 7. 数える

「登録者数」は LINE（`U…`）とメール（`m:…`）を分けて数える。同じ人が両方で入ると2人になる（合わせないと決めたため）。
